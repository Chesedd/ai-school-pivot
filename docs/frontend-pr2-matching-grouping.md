4. **Matching endpoints:** `POST /api/assessment-core/scan-batches/{batch_id}/match`; `GET /api/assessment-core/scan-batches/{batch_id}/matching`. The GET is both status and proposal retrieval.
5. **Grouping endpoints:** beneath `/api/assessment-core/scan-batches/{batch_id}`: `GET /grouping`, idempotent `POST /grouping` to initialize a missing draft, `PATCH /grouping/pages/{page_id}`, `PUT /grouping/groups/{participant_id}/page-order`, and `POST /grouping/confirm`. No new endpoints.
6. **Routes:** `/classrooms/{classId}/assignments/{assignmentId}/paper/{batchId}/matching` now renders the real workspace. The existing intake CTA enters it. `/checking` is added beneath the same batch path as a placeholder. Both routes use the existing scan capability gate and validate assignment/class and batch/assignment ownership through reads.
7. **Start:** only after completed intake, ready pages, and a nonempty real roster, with no existing matching run. One guarded mutation; no invented idempotency header. The backend owns run claims/replay. Existing running matching never starts another run.
8. **Polling:** the existing React-hook style is used; no query library exists in the package. Reads are serialized, scheduled three seconds after completion, and aborted on unmount. Polling runs while matching reports `running` or its start request is outstanding. Stable results and failures stop it. Hidden tabs pause; focus/visibility revalidate. Stable grouping mutations do not initiate polling.
9. **Failure/retry:** `failed_retryable` with batch `matching` exposes “Продолжить сопоставление”, using the same POST resume contract. `failed_terminal` exposes no retry. Read/mutation failures have bounded messages; conflict responses trigger fresh reads. The matching read response does not expose failure detail or lease expiry.
10. **Proposal mapping:** `proposals[].page_id` connects evidence to metadata; `proposed_student.display_name`, `candidate_students[].display_name`, `disposition`, and `warning` supply teacher context. Server initialization seeds matched pages with valid participants and leaves ambiguous/unmatched/invalid matches unresolved. Confidence, evidence summaries, provider reasoning, group tokens, and telemetry are not rendered.
11. **Page states:** “Не распределена”, “В черновике”, and confirmed “Назначена” follow actual grouping membership/status. “Предложено” appears in selected-page context. “Нужно проверить” uses matching warning or unresolved ambiguity/invalid-match evidence; it does not invent confidence.
12. **Images:** metadata comes from `GET /scan-batches/{batch_id}/pages`; only the selected image is fetched as an authenticated blob from `GET /api/assessment-core/scan-pages/{page_id}/content`. The client uses the authorized route, never storage references. Object URLs are revoked, requests aborted, aspect ratio preserved, fit/zoom controls supplied. Missing/purged/unauthorized content is bounded within the viewer. There is no original PDF fallback and no eager thumbnail/full-image fan-out.
13. **Roster/groups:** the existing `getAssignmentResults` client reads `/api/assessment-core/assignments/{assignment_id}/results?offset=…&limit=100`, paging by `participant_count` and retaining only participant IDs/display names. One request for 30 students, one per roster page for larger rosters. Groups use backend membership/order; empty students are compact targets. Canonical variant IDs are resolved to read-only names from the existing assessment projection.
14. **Unassigned pages:** the always-present “Не распределены” area displays every server unresolved page. The complete left strip also displays every extracted page, independently of roster search. No page is dropped, ignored, or locally assigned by inference.
15. **Drag-and-drop:** added established `@dnd-kit/core`, `sortable`, and `utilities`; eight-pixel pointer activation threshold; strip-to-student, cross-student, student-to-unassigned, and within-paper reorder. Drag IDs remain internal; screen-reader announcements use page numbers and student names. Four semantic drag-operation tests cover results without pointer-physics simulation.
16. **Non-drag assignment:** select a page, type a display-name filter, choose a native select target showing page counts, and press “Назначить”. “В нераспределённые” removes membership. All core operations are keyboard operable. There is no modal or extra confirmation dialog.
17. **Reorder:** up/down buttons send the complete ordered `page_ids` list to the PUT route, with current CAS values. The same operation handles sortable drops. Original global page numbers stay stable while paper order changes.
18. **Persistence:** every membership/reorder action is immediately saved in the backend draft and then read back. No optimistic academic membership, localStorage, IndexedDB, dirty draft, or fabricated academic identity. Selection/search/zoom are ephemeral React state. Reads and mutations share the existing authenticated request client.
19. **Concurrency:** PATCH, PUT, and confirm send `expected_revision = grouping_revision` and `expected_row_version = row_version` from the displayed snapshot. Failed/stale actions never automatically resend or force-write. Fresh authoritative reads replace old membership; read failures remove actionable stale data. Focus refresh also detects another teacher's changed/confirmed revision.
20. **Confirmation:** one “Подтвердить распределение” action, guarded against duplicate clicks, uses the exact CAS confirmation body. The backend validates and creates one canonical paper submission per nonempty participant group, moving the batch through `grouping_confirmed` to `ready_for_checking` in its transaction. No checking call follows.
21. **Completeness:** unresolved pages, missing/duplicate coverage, duplicate participants, empty groups, or absent canonical variants disable the CTA. The count uses unique assigned page IDs. Server validation remains final, including page readiness and operational limits.
22. **Canonical identity/variant:** only backend participant IDs are sent as assignment targets. Student IDs and variant IDs are never sent in grouping mutations. Variant names are read-only. Backend confirmation checks canonical variants; no frontend variant-mismatch DTO/code is invented.
23. **Advanced states:** confirmed/advanced grouping is read-only for `ready_for_checking`, `checking`, `checking_completed`, and `completed`; grouping controls and restart actions are absent. Page selection/inspection and roster filtering remain available. Cancelled batches preserve their actual draft/confirmed status, keep selection available, and expose neither edits nor a checking handoff.
24. **Handoff:** “Перейти к проверке” enters the placeholder, which describes the current batch boundary and links back to grouping. No checking execution, progress, review, grades, or PR3 features.
25. **Errors:** centralized exact-code mappings cover `matching_already_running`, claim/outcome uncertainty, intake not ready, `grouping_revision_conflict`, `grouping_based_on_stale_matching`, immutability/state advance, invalid membership/order/participants, `grouping_variant_required`, `unmatched_pages_block_confirmation`, duplicate membership/participant, coverage mismatch, paper conflicts/limits, and matching failures. Authorization is status-bounded. Unknown 5xx/network/422 responses never render raw details. Browser failure acceptance exposed a misleading form-validation fallback for an actual matching 422; that was corrected and tested, without a baseline-failure claim.
26. **Responsive:** desktop grid provides page strip, central viewer, and roster/groups. Page/group lists scroll; the desktop viewer bounds its content and the footer remains reachable below the workspace with sticky behavior on scrolling. Below 1000px the workspace stacks with a horizontal selector, viewer/assignment controls, groups, then actions. No three-column squeeze at 760px.
27. **Accessibility:** native selection buttons expose pressed state and visible focus, readable textual status/errors, labelled searches/select, meaningful image alt text, keyboard assignment/removal/reorder, nearby completeness explanation, and Russian drag announcements. Disabled dragging does not disable read-only page selection. No drag-only operation or dialog focus-management substitute.
28. **Large-batch sanity:** a 60-page/30-student fixture with long names renders all pages and groups, makes one roster request, and loads one full image. Selecting a different page loads only that image. A 101-student pagination test proves the roster is not truncated. No frontend request per student; no formal benchmark.

37. **Missing/narrow backend capabilities:** no dedicated scan roster or thumbnail endpoint; the full assignment-results projection is reused for names only. That projection requires `assessment.results.read` and assessment-owner access, narrower than scan-batch authorization for another teacher of the class; the inherited assignment/assessment context routes have similar ownership constraints. Such users receive bounded unavailable feedback rather than invented participants. A shared-teacher roster/context projection is a backend follow-up, outside this frozen scope. Matching GET omits detailed failure/lease recovery metadata, so a still-`running` lease is never treated as a user-retry opportunity. There is no exposed useful roster-alias projection; no alias editor was added.
38. **Deliberate UX choices:** numeric page tiles replace thumbnails because no small-image route exists; only the selected full page is fetched.
